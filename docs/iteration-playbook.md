# Skill 迭代手册

作者：范范之辈

这份手册用于把真实课程样本、复盘反馈和评分校准持续沉淀进课程七段 skill。

## 迭代目标

每次迭代优先提升三件事：

1. 诊断更准：能稳定识别七段任务缺口，而不是只看标题。
2. 改稿更能落地：每条建议都能变成结构动作或话术动作。
3. 方法更可迁移：从案例里提炼原理、原则、方法和检查项。

## 推荐迭代循环

```text
真实材料 -> 脱敏 -> 结构诊断 -> 用户校准 -> 原理提炼 -> 修改 skill -> 回归测试 -> 发布
```

不要把真实逐字稿直接放进公开仓库。优先放入：

- 合成样例
- 脱敏结构片段
- 改造前后对照的抽象版本
- 用户确认过的评分锚点
- 通用检查项

## 每次复盘要记录什么


## 什么时候改 SKILL.md

只有当变化影响触发、模式选择、必须读取的参考文件或核心工作流时，才改 `SKILL.md`。

适合改 `SKILL.md`：

- 新增一种稳定使用场景，比如“原则提炼”。
- 发现用户常用说法不能触发 skill。
- 需要新增一个必须读取的参考文件。
- 教学/销讲边界规则影响主流程。

不适合改 `SKILL.md`：

- 只是新增一个案例。
- 只是补一句具体话术。
- 只是记录某个老师的表达风格。

## 什么时候改 references

适合改 references：

- 新增二级任务、三级验收点或不能升档规则。
- 提炼出通用改稿方法。
- 某类课型有稳定的结构风险。
- 真实样本反复暴露同一诊断误判。

## 什么时候改 evals

适合改 evals：

- 用户明确校准了某份稿应该是 3/5/7/9 分。
- 出现一次典型误判，未来必须避免。
- 新增功能需要回归测试，比如教学/销讲分流、原则提炼、成熟稿判断。

## 下一批最值得补的资料

1. 训练营单课：成熟稿、一般稿、问题稿各 1 份，附用户心中评分。
2. 交付课：7 分但不能到 9 分的样例，附原因。
3. 讲师反馈：同一诊断分别给课程顾问、教研、讲师看的版本。
4. 改造前后：同一节课的原稿、重构方案、用户确认后的最终稿。
5. 整课混合样本：教学和销讲都存在，用于测试边界识别。

## 发布前检查

- README 是否仍能说明安装、调用、输入模板、输出模式。
- `SKILL.md` 是否保持简洁，没有塞入长案例。
- 新增参考文件是否被 `SKILL.md` 路由。
- 公开样例是否全部脱敏或合成。
- 本地 skill 是否同步到 `~/.codex/skills/course-seven-segment-designer`。
