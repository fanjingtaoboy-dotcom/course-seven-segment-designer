# Teacher-Facing Feedback

Use this reference when the user says the output is for 自己, 讲师, 课程顾问, 教研, 排练, 讲师沟通, or 改逐字稿.

## Tone

Be direct but teacher-safe. Do not attack the teacher's personality, credibility, or effort. Frame problems as learner-effect problems and give concrete wording actions.

Prefer:

```text
这里建议压缩，因为学员此时还没有形成今天的学习任务，过多背景会延迟进入需求。
```

Avoid:

```text
老师太啰嗦。
```

## Default Output

```text
一、整体判断
二、建议保留
三、建议压缩或删除
四、需要重说的关键段
五、需要补的转场
六、实操/案例/作业验收标准
七、讲师排练清单
```

## Feedback Categories

| Category | What to include |
|---|---|
| 保留 | effective trust, vivid scene, strong case, clear step, useful interaction, teacher-specific warmth |
| 压缩 | repeated greetings, authority stacking, reward repetition, side stories, redundant theory |
| 重说 | need framing, pain cause, principle model, action standard, next-lesson value |
| 补转场 | need -> pain, pain -> principle, principle -> practice, practice -> summary, summary -> action |
| 补验收 | pretest, step order, intermediate judgment, retest, mistakes, homework standard |
| 排练 | sentences to memorize, sections to shorten, interaction timing, board/camera prompts, assistant cue |

## Keep/Change/Rewrite Format

Use this format for practical teacher notes:

| Location | Keep | Change | Rewrite action |
|---|---|---|---|
| section/timestamp | what works | what blocks learners | what the teacher should say/do instead |

## Rehearsal Checklist

For a practice delivery class, end with a rehearsal checklist:

```text
开场 3 分钟内是否说清今天学什么？
学员愿望是否被转成今天的能力目标？
痛点是否说出旧做法、原因、代价、误区？
原理是否能被学员用一句话复述？
实操是否有步骤、判断、验证、易错提醒？
总结是否压成 1-3 个记忆点？
作业是否有对象、格式、标准、反馈路径？
明天到课理由是否承接今天，而不是只靠福利？
```
