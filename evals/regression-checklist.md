# 回归检查清单

每次更新课程七段 skill 后，用这份清单做快速检查。

## Trigger Quality

- 明确提到 `$course-seven-segment-designer` 时必须触发。
- 用户自然说“课程七段结构、直播课结构诊断、逐字稿评分、课程改稿、金字塔重构、训练营单课交付效果”时应触发。
- 用户只问价格、优惠、成交、定金、报名、案例佐证时，应优先建议或使用 `$sales-conversion-eight-segment`。

## Diagnosis Quality

- 先给资料边界和学员分析，不把推断说成事实。
- 只使用七个顶层模块。
- 生产标签、奖励、作业、助教承接、明日预告不新增为第八模块。
- 逐段判断存在、功能、心理推进、咬合和阻力。
- 至少指出最影响结构分数的 1-3 个关键问题。
- 对成熟稿，区分“交付成熟”与“结构满分”。

## Principle Extraction Quality

- 从案例中提炼原理、原则、方法、检查项和脱敏样例。
- 不复述私密逐字稿，不沉淀老师口头风格、机构私域动作或不可验证个案。
- 能说明某条规则对应哪一段、哪一个二级任务、哪一个学习心理变化。

## Scoring Quality

- 正式评分必须输出总分、最接近锚点、不能给更高分的原因、升档优先任务。
- 不因为逐字稿长、气氛热闹、互动多、老师权威强就给高分。
- 不能升档规则必须和二级任务/三级验收点对应。

## Rewrite Quality

- 重构必须是七段金字塔，不只是七个标题。
- 每段至少包含重构目标、二级任务、关键验收点或话术落点。
- 优化话术后要说明关键句修复了什么任务、推动了什么心理变化。

## Cross-Skill Boundary

- 整课逐字稿必须先识别教学主链和销讲主链。
- 教学评分不吸收报价、优惠、赠品、名额、报名播报。
- 销讲开始前要检查教学是否形成 S0 获得感。
- 作业、次日到课、报名购买同时出现时，要判断是否互相打架。

## Minimum Passing Standard

一次更新可以发布，至少要满足：

1. `SKILL.md` frontmatter 合法。
2. 新增参考文件被 `SKILL.md` 明确路由。
3. README 能让新用户完成安装和第一次提问。
4. 不包含未经允许的原始私密课程内容。
5. 用 3 个以上测试提示检查后，没有出现第八课程模块或教学/销讲混淆。
