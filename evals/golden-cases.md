# 黄金评测样例

这些样例用于回归测试课程七段 skill。它们是合成或脱敏结构样例，不包含真实私密逐字稿。

## 评测方式

每次更新 skill 后，用 `evals/test-prompts.md` 和本文件中的样例提问，检查输出是否满足：

1. 先做学员分析或明确推断边界。
2. 只使用七个顶层课程模块，不新增第八模块。
3. 判断功能，不只看标题。
4. 正式评分必须说明不能升档原因。
5. 改稿建议必须转成具体结构动作或话术动作。
6. 遇到销讲内容时，先做边界识别，并建议使用 `$sales-conversion-eight-segment` 单独诊断。

## Case 1：1 分档，只有知识堆叠

```text
课程标题：三步提升表达力
内容：老师先介绍自己非常有经验，然后讲表达很重要，接着列出十个表达技巧，最后说大家回去多练。
目标学员：未提供
```

Expected behavior:

- 标注目标学员、课型、课后行动为缺失或推断。
- 不能因为有“开场、知识、总结”就给高分。
- 识别为七段严重缺失或功能失控，接近 1 分。
- 指出最先补的是目标学员、学习理由、痛点原因、可复述模型和行动标准。

## Case 2：3 分档，七段影子存在但功能弱

```text
大纲：开场欢迎；让大家说自己最想解决的问题；讲三个专业概念；老师演示一次；回顾今天讲了三个点；布置作业。
```

Expected behavior:

- 识别“问题收集”不等于合格的引发需求。
- 识别“老师演示一次”不等于合格的实操转化。
- 通常不能超过 3 分或低 5 分，除非补充材料证明二级任务完整。

## Case 3：5 分档，有结构但主线和转化弱

```text
课程有目标学员和主题，也有痛点、原理、案例、练习和作业。但痛点讲了很多泛泛后果，原理讲了多个模型，案例之间没有统一标准，作业只有提交要求没有合格标准。
```

Expected behavior:

- 判断七段大体存在。
- 分析主线拥挤、原理不可复述、实操缺少判断和验证。
- 一般落在 5 分左右，不能给 7 分的理由是二级任务未稳定完成。

## Case 4：7 分档，成熟交付但未到 9

```text
训练营单课：开场清楚，目标学员明确，有自测、痛点原因、一个清晰方法、两轮实操、作业和明日预告。问题是总结只复述流程，作业标准不够细，明日预告主要靠奖励和提醒。
优先级：交付效果、次日到课、交作业。
```

Expected behavior:

- 区分“成熟交付”与“结构 9 分”。
- 认可其接近 7 分。
- 不能给 9 分的理由应落在记忆结构、作业标准、次日到课与今日收获的自然衔接。

## Case 5：9 分档，高标准课程结构

```text
课程以一个明确学员场景开场，快速建立信任；把表层愿望收束成共同学习目标；拆出旧做法、原因、误区和后果；用一个可复述模型解释原理；用两个案例或动作演示模型如何应用；总结成公式或清单并提醒易错点；结尾给出一个低阻力作业、合格标准、反馈路径和下一课逻辑。
```

Expected behavior:

- 不因文本较短而降分，重点看结构功能。
- 判断七段咬合稳定，二级任务基本完整。
- 如给 9 分，需要说明仍受限于“这是结构样例，不是完整逐字稿证据”。

## Case 6：教学与销讲混淆

```text
一节直播课前 60 分钟讲方法和演示，后 20 分钟介绍进阶课、报价、优惠、名额、学员案例和报名路径。用户要求：给课程七段打分。
```

Expected behavior:

- 先识别教学主链与销讲主链边界。
- 只对教学主链做七段评分。
- 把价格、优惠、名额、报名路径、销讲案例标注为销讲八段内容。
- 建议用 `$sales-conversion-eight-segment` 单独诊断销售链。

## Case 7：原则提炼，不要案例复述

```text
用户提供一份复盘讨论，说原诊断太像具体案例总结，要求提炼课程结构的原理、原则、方法。
```

Expected behavior:

- 输出 `原理 -> 原则 -> 方法 -> 检查项 -> 脱敏样例`。
- 具体行业案例只能作为辅助样例。
- 明确哪些内容适合沉淀进 skill，哪些只属于个案表达或私密材料。
